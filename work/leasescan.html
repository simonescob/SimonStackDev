Case Study

LeaseScan

AI lease analysis software that reads commercial lease documents and extracts the terms, dates, and risk clauses that matter — turning hours of manual review into seconds.

RoleFull-Stack Developer
StackNext.js · OpenAI · PostgreSQL
Year2025

Overview

LeaseScan is a document intelligence platform for commercial real estate teams, tenant-rep brokers, and small business owners who need to understand what's actually in a lease without paying for hours of legal review. A user uploads a lease PDF, and LeaseScan extracts and summarizes the critical data points: rent schedule, escalation clauses, renewal and break options, key dates, and any unusual or high-risk provisions.

I built the entire application — the document ingestion pipeline, the AI extraction engine, the structured data model, and the review dashboard — and deployed it on Vercel.

Technical Stack

Next.js 14 TypeScript OpenAI API PostgreSQL Supabase Vercel Blob Tailwind CSS Zod

The Problem

Commercial leases are long, dense, and full of consequential details buried in legalese. A single missed renewal deadline or misunderstood escalation clause can cost a business tens of thousands of dollars. Yet reviewing a lease properly traditionally means either reading 40+ pages of contract language yourself or paying a real estate attorney by the hour. Smaller businesses and busy brokers needed a faster way to get the essential facts.

Architecture & Implementation

LeaseScan is a Next.js App Router application deployed on Vercel. Uploaded lease PDFs are stored in Vercel Blob, then the document text is extracted server-side. Because leases can run to dozens of pages, the extraction pipeline chunks the document intelligently and preserves section context so the AI can correctly associate clauses with their headings.

The extraction engine prompts the OpenAI API to pull a fixed schema of lease attributes — tenant and landlord, premises, term length, commencement and expiration dates, base rent, escalation structure, renewal options, break clauses, security deposit, and flagged risk provisions. Every field is returned as structured JSON, validated with Zod, and persisted to PostgreSQL via Supabase. Crucially, each extracted value carries a citation back to the source text, so users can verify any data point against the original lease language.

The data model is designed so that key dates (renewals, breaks, expirations) become first-class, queryable records — enabling reminder and portfolio-level features where users track obligations across multiple leases from a single dashboard.

Key Features Delivered

The review dashboard presents an at-a-glance summary card for each lease — rent, term, key dates, and a risk indicator — backed by a detailed view where every extracted clause links to its source citation. Users can flag clauses for follow-up, add notes, and export a clean summary report to share with stakeholders.

A portfolio view aggregates all of a user's leases, surfacing upcoming critical dates so nothing slips through the cracks. Multi-tenant data isolation is enforced with Supabase row-level security, and authentication supports both email magic links and Google OAuth.
