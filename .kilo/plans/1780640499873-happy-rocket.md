# SEO/AEO Critical Fix Plan — simonstackdev.com

## Summary
The site has excellent on-page tags and structured data, but **cannot be reliably crawled or indexed in its current state** because the entire DOM is reconstructed client-side from an embedded bundle. This plan restores real HTML delivery and completes the critical missing signals that block ranking and AI answer engine inclusion.

## Sorted by Priority

### P0 — CRITICAL (blocks all traffic; fix first)

1. **Eliminate the client-side bundler / DOM replacement pattern**
   - Replace the embedded base64 manifest + `DOMParser` + `document.documentElement.replaceWith(...)` flow with a real static HTML build output for every page.
   - `index.html`, `work/leadpulse-ai.html`, `work/pitchlens.html`, and `work/leasescan.html` must contain fully rendered, semantically structured content in the initial HTTP response.
   - Acceptable approaches: Astro SSG, Next.js `output: 'export'`, or a custom build step that emits plain HTML with inline CSS for critical above-the-fold styles.
   - Do NOT rely on noscript fallback as the primary crawlable surface; make it a true fallback only.

2. **Serve a real `<img>` LCP candidate with explicit dimensions**
   - Replace the SVG placeholder used before hydration with an actual `<img src="/og.png" width="1200" height="630" fetchpriority="high">` in the initial HTML.
   - Set `width` and `height` on the img to prevent CLS.
   - Use WebP/AVIF variants if possible.

3. **Add favicon and PWA touch icons**
   - `favicon.ico` at `/`
   - `apple-touch-icon.png` (180x180) referenced in `<head>`
   - Optional: `manifest.json` with `icons` and `name`/`short_name` fields.

### P1 — HIGH (unlock rankings and rich results)

4. **Add `Article` structured data to all three case study pages**
   - Use `@type: Article` with `headline`, `author` (reference `#person`), `publisher` (reference `#website`), `datePublished: 2025-01-01` (or actual project date), `dateModified` (match page lastmod), and the existing `about` linkage.
   - Keep the existing `SoftwareApplication` and `BreadcrumbList` nodes; append `Article` to each page's `@graph`.

5. **Generate unique OG/thumbnail images per page**
   - Hero image for the homepage (current `og.png` is acceptable but should be renamed to `hero-home.png` for clarity; keep using it only if it matches the page brand).
   - Case-study-specific OG images:
     - `og-leadpulse-ai.png` — lead scoring dashboard / CRM visual
     - `og-pitchlens.png` — pitch deck analysis visual
     - `og-leasescan.png` — lease document extraction visual
   - All images: 1200x630, PNG or WebP, with descriptive alt text matching the page context.

6. **Add webmaster verification meta tags**
   - Google Search Console `<meta name="google-site-verification" content="...">`
   - Bing Webmaster Tools `<meta name="msvalidate.01" content="...">`
   - Place in `<head>` of `index.html` and case-study pages after the user provides verification codes.

7. **Harden `Person` schema in index.html**
   - Add `telephone`, `address` with at least `addressCountry: "CO"`, and `knowsLanguage: ["English", "Spanish"]`.
   - Add `jobTitle` variations if applicable (e.g., "Freelance Developer for US Startups").

### P2 — MEDIUM (polish and competitive parity)

8. **Add `image:image` entries to sitemap.xml for case study pages**
   - Mirror the homepage pattern: `<image:image><image:loc>...</image:loc><image:title>...</image:title></image:image>` for each of the three `/work/*` URLs.

9. **Add `hreflang` and `x-default` annotations**
   - `<link rel="alternate" hreflang="en" href="https://simonstackdev.com/" />`
   - `<link rel="alternate" hreflang="x-default" href="https://simonstackdev.com/" />`
   - Add to `index.html` and case-study pages.

10. **Add resource hints for font and CDN performance**
    - Preconnect to `fonts.googleapis.com` and `fonts.gstatic.com` in `index.html` (already partially present in the JS bundle template; ensure it is in the outer shell too if P0 splits the document).
    - Preload `og.png` and favicon.

### P3 — LOW (small cumulative wins)

11. **Add `<title>` and `<desc>` inside `#__bundler_thumbnail` SVG for accessibility**
    - Only relevant if the SVG persists; moot if P0 removes it.

12. **Add response security headers via Vercel config**
    - `X-Content-Type-Options: nosniff`
    - `Referrer-Policy: strict-origin-when-cross-origin`
    - `Permissions-Policy: geolocation=(), microphone=(), camera=()`
    - Implement via `vercel.json` `headers` route rules.

13. **Validate structured data on a schedule**
    - Run `index.html` and each case study through the [Rich Results Test](https://search.google.com/test/rich-results) and [Schema.org validator](https://validator.schema.org/) after each P0–P2 deployment.
    - Fix warnings before submission to Search Console.

## Execution Order
1. P0 items first (rendering + LCP image + icons)
2. P1 in parallel (OG images can be created while Article schema is drafted)
3. P2 once P0 is live and crawlable
4. P3 trailing cleanup

## Success Criteria
- Initial HTML response (View Source) contains full readable content for every page.
- Rich Results Test passes for all JSON-LD.
- Core Web Vitals thresholds met in PageSpeed Insights for mobile and desktop.
- AI answer engine (Perplexity/ChatGPT Search) cites the site correctly within 8 weeks of P0 deployment.
