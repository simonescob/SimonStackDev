# SEO/AEO Improvement Plan for simonstackdev.com

## Status (from Audit)

| Item | Current State |
|---|---|
| `robots.txt` | ✅ Present with AI crawler allowlisting |
| `sitemap.xml` | ✅ Present — but only lists `/` (homepage) |
| Meta description | ⚠️ Generic "Portfolio of Simón Escobar..." on some tags |
| Stats counters | ❌ Showing `0+ / 0%` at runtime (JS-only counters not pre-rendering) |
| FAQ section | ⚠️ Schema exists in JSON-LD, but FAQ is JS-only (not in noscript fallback visible to bots) |
| Blog/content pages | ❌ None |
| Schema markup | ⚠️ Person, WebSite, WebPage, FAQPage, Services present — but truncated/incomplete |

**Note:** The audit flagged descriptors like "Meta description says 'Portfolio'" and "Stats counters showing 0+ / 0%" — these were detected at crawl-time when the JS had not yet populated values. The noscript fallback has hardcoded stat values (`5+`, `30+`, `100%`, `∞`) and partial FAQ markups, but the visible FAQ section in the rendered app is missing.

---

## Tasks by Priority

### 1. Fix Stat Counters (Pre-render for crawlers) — HIGH
**What:** Add a static `<noscript>` stat section (or enhance the existing one) so crawlers who don't execute the JS bundle always see the real values (`5+`, `30+`, `100%`, `∞`).
**Why:** JS-only animated counters show `0+ / 0%` until the JS executes. Google/SEO bots and screen readers may not execute the full bundle. Pre-rendered static counters are a zero-risk, immediate fix.
**Files:** `index.html`
**Change:** Ensure the noscript `<section>` with stat counters is comprehensive and placed before the `<noscript>` tag closes. The static values already exist (lines 247–267) — confirm they cover all four counters.

### 2. Add an Explicit FAQ Section to the Visible (Non-JS) HTML — HIGH
**What:** Add a visible FAQ section (`<dl>` with `<dt>`/`<dd>` Q&A pairs) inside the `<noscript>` block of `index.html`. These will be visible to crawlers that don't execute JS.
**Why:** Currently the FAQ schema exists in JSON-LD (lines 115–149) but the visible FAQ section only has Q&A text — no structured question/answer markup. Adding a proper `<dl>` FAQ to the noscript fallback reinforces the FAQPage schema to non-JS crawlers.
**Files:** `index.html`
**Change:** Add a `<section><h2>Frequently Asked Questions</h2><dl>...</dl></section>` block inside the existing `<noscript>` div, with the same 4 Q&A items already in the JSON-LD.

### 3. Update Meta Description to Be More Descriptive — MEDIUM
**What:** Replace the generic "Portfolio of Simón Escobar, a senior full-stack developer..." meta description with one that actually lists technologies and value proposition matching the page content.
**Why:** The audit noted "Meta description says 'Portfolio'" — meaning the snippet was picked up from a tag with "Portfolio" text rather than a proper `<meta name="description">`. This helps click-through rate on SERPs.
**Files:** `index.html`
**Current:** `<meta property="og:description" content="Portfolio of Simón Escobar, a senior full-stack developer building modern web applications with React, Next.js, Node.js, and TypeScript.">`
**Proposed:** `<meta property="og:description" content="Simón Escobar is a senior full-stack developer specializing in React, Next.js, Node.js, and TypeScript. Building fast, scalable, SaaS products, REST APIs, and GraphQL backends.">`

### 4. Enhance JSON-LD Schema — MEDIUM
**What:** The JSON-LD is working (Person, WebSite, WebPage, FAQPage, Services present) but the `Person` `knowsAbout` and `sameAs` could be expanded and the schema could be tightened.
**Files:** `index.html` lines 52–200
**Changes:**
- Add `telephone` or `email` to the `Person` entity  
- Add `aggregateRating` if testimonials are available (or skip if none)
- Ensure `Service` entities all have `offers` (only the first one currently has it)
- Add `BreadcrumbList` to the `@graph` for the homepage

### 5. Add Static Case Study / Project Pages — LOWER (but highest SEO value)
**What:** Create dedicated HTML pages for the main projects: `/work/leadpulse-ai`, `/work/pitchlens`, `/work/leasescan` — each with proper title, meta description, content (300+ words), and JSON-LD.
**Why:** The audit flagged that project links currently go to Vercel staging URLs (`pitch-lens-front.vercel.app`) instead of own-domain URLs. Own-domain pages capture long-tail queries and give AI engines something to cite. This is the biggest SEO value item but requires creating new files.
**Files:** New: `work/leadpulse-ai.html`, `work/pitchlens.html`, `work/leasescan.html` (or `/work/leadpulse-ai/index.html` etc.)
**Each page needs:**
- Proper `<title>` and `<meta name="description">`
- 300+ words of case study content
- at least `WebPage` JSON-LD
- `<link rel="canonical">` to own-domain URL
**sitemap.xml update:** Add all new URLs

### 6. Add Blog/Content Pages — LOWER ROI
**What:** Create a simple `/blog/` section with 2–3 long-form articles targeting key queries (e.g., "AI lead scoring tools", "pitch deck analyzer", "lease analysis software").
**Why:** The audit found no blog/content pages — providing blog content enables long-tail keyword capture and gives AI citation fodder.
**Files:** New: `blog/index.html`, `blog/ai-lead-scoring-tools.html`, etc.
**sitemap.xml update:** Add all new URLs

### 7. Internal Link Structure Cleanup — LOWER
**What:** Update all project links in the `<noscript>` section and in JSON-LD acceptedAnswer fields to point to `/work/<slug>` instead of external Vercel URLs.
**Files:** `index.html`
**Effect:** Keeps link equity on the domain.
